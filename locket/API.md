# Locket API

Контракт между сервером (`server/`) и iPhone-приложением (`ios/`). Сервер — источник правды. Если меняешь здесь — меняй и там.

- База — `PUBLIC_URL`. JSON в UTF-8. Время — миллисекунды с 1970 года (число).
- Авторизация: `Authorization: Bearer <token>`.
- Ошибка — HTTP-статус и `{ "error": "<по-русски: что случилось и что делать>" }`. Приложение показывает этот текст как есть.

## Модель

**Аккаунт = пароль.** Логина нет. Пароль, который уже есть, впускает в свой аккаунт. Новый пароль создаёт новый аккаунт — но только вместе с первым фото.

- Пароль: от 4 до 64 символов после нормализации NFC; пробелы не обрезаются. Длина считается в символах (`[...password].length`).
- Сервер хранит `password_key = HMAC-SHA256(pepper, NFC(password))` в hex с уникальным индексом: поиск идёт по паролю, а утёкшая база без pepper бесполезна.
- Pepper берётся из `PASSWORD_PEPPER`, а если переменной нет — из файла `<DATA_DIR>/pepper`. Файл создаётся при первом запуске: 32 случайных байта в hex. **Без pepper никто не войдёт.** Он лежит в папке данных и бэкапится вместе с базой.
- Юзернейм вписать нельзя — его выбирают из трёх предложений сервера. До выбора `username = null`. Юзернейм уникален по ключу `username_key`: нижний регистр и «ё» → «е». В этой версии сменить его нельзя.
- Друзья: заявка, потом принятие. Дружба взаимная, максимум `MAX_FRIENDS` (100).
- Неделя та же: закрывается в воскресенье в 21:00 по Москве (`week.js`).

### Закрытые фото

Для зрителя V, друга A и недели W:

```
allowance(V, W) = 1 + (сколько фото V выложил за неделю W)
```

Фото A за неделю W сортируются по `(created_at, rowid)` по возрастанию. Фото с индексом `i` (с нуля) открыто для V, если `i < allowance(V, W)`.

- Первое фото друга за неделю видно всегда. Каждое твоё фото за эту неделю открывает тебе ещё по одному фото **каждого** друга за ту же неделю.
- Свои фото открыты всегда.
- Правило действует и для прошлых недель: счёт остаётся таким, каким был в ту неделю.
- Закрытое фото приходит без содержимого (см. `Photo`). Его нельзя оценить (403), оно не попадает в виджет, и пуш о нём приходит без картинки.
- Исключение — посты-победители в итогах (пост недели, посты дня, самые креативный, смешной и безбашенный посты): их картинка видна всем, кто видит итоги, потому что это приз.

## Оценки вслепую

Звёзды и реакции тайные. Никто не видит, сколько звёзд или реакций у фото и кто что поставил, — даже автор. Так никому не обидно за «2 из 3».

- В `Photo` есть только то, что поставил сам зритель: `myStars` и `mine`. Сумм, средних, счётчиков и списков оценивших нет ни в одном ответе.
- Пока неделя идёт, итогов нет: `GET /api/week/current` отдаёт только даты и `photoCount`. Ни лидера, ни очков, ни таблицы.
- Когда неделя закрывается, называются только победители — имена и посты, без цифр.
- Пуш автору говорит, кто оценил, но не как: «барсук — что именно, секрет. Победителей объявим в воскресенье».

## Эндпоинты

### Вход

**`POST /api/auth/password`** — без авторизации.

```json
{ "password": "..." }
```

| Ответ | Когда |
| --- | --- |
| `200 { "status": "signedIn", "token": "...", ...Me }` | такой пароль есть: вход |
| `200 { "status": "new" }` | такого пароля нет; аккаунт **не** создаётся |
| `400 Пароль — минимум 4 символа` / `Пароль — не длиннее 64 символов` | |
| `429 Слишком много попыток — подожди 10 минут` | 20 ответов `new` за 10 минут с одного IP |

IP: при `TRUST_PROXY=1` (так за Caddy) берётся первый адрес из `X-Forwarded-For`, иначе — адрес сокета.

**`POST /api/auth/register`** — без авторизации, JSON до 12 МБ.

```json
{ "password": "...", "photo": "<JPEG в base64>", "caption": "необязательно, до 60 символов" }
```

- Пароль проверяется так же. Фото — JPEG (`FF D8 FF`) не больше 8 МБ после декодирования; иначе `400 Нужна картинка в формате JPEG` или `413 Слишком большой файл`.
- Если такой пароль уже есть (кто-то успел раньше), это вход: фото публикуется в тот аккаунт как обычное. Ответ: `200 { "status": "signedIn", "token", ...Me }`.
- Иначе в одной транзакции создаются пользователь (`username = null`) и его фото. Ответ: `200 { "status": "created", "token", ...Me }`.
- Не больше 10 новых аккаунтов в час с одного IP, иначе `429 Слишком много новых аккаунтов — попробуй через час`.

**`POST /api/auth/logout`** — как раньше: `{ "deviceToken"?: "..." }` → `{ "ok": true }`.

### Профиль и юзернейм

**`GET /api/me`** → `Me`

```json
{
  "user": { "id": "…", "username": "барсук" },
  "friends": [{ "id": "…", "username": "ярослава" }],
  "incomingRequests": 1,
  "week": { "id": "2026-W42", "startsAt": 0, "endsAt": 0 },
  "birthday": "11-14" | null,
  "askBirthday": false
}
```

`username` равен `null`, пока юзернейм не выбран. Друзья отсортированы по `username_key`.

### День рождения

Только день и месяц, год не спрашиваем. Видят друзья: рядом с именем в списке друзей и в виш-листе.

- `askBirthday` — пора спросить: юзернейм выбран, даты нет, своих фото уже 3 или больше, и «Не сейчас» не нажимали последние 30 дней. Приложение показывает вопрос вверху ленты.
- **`PUT /api/me/birthday`** `{ "month": 11, "day": 14 }` (числа или строки) → `Me`. Несуществующая дата — `400 Такой даты нет`; 29 февраля можно.
- **`DELETE /api/me/birthday`** → `Me`. Дата убирается, напоминаний больше нет.
- **`POST /api/me/birthday/later`** → `Me`. «Не сейчас»: вопрос вернётся через 30 дней.

**Напоминания.** Каждый день с `BIRTHDAY_HOUR` (по умолчанию 10:00 по времени недели) сервер смотрит, у кого из друзей день рождения через 30 дней, через 5 дней или сегодня. Друзьям уходит пуш `birthday`, в сам день самому человеку — «С днём рождения!». Метка `birthday:<userId>:<дата>` в `jobs` — один раз в день; если сервер лежал весь день, пуш не досылается. 29 февраля в невисокосный год празднуется 28-го.

**`GET /api/usernames/suggestions`** → ровно три свободных варианта, по одному каждого вида:

```json
{ "suggestions": [
  { "username": "барсук", "kind": "animal" },
  { "username": "мудила7", "kind": "swear" },
  { "username": "ярослава", "kind": "name" }
] }
```

- Слова лежат в `server/src/usernames.js`: `USERNAME_WORDS = { animal: [...], swear: [...], name: [...] }`. Все слова в нижнем регистре, кириллицей, без пробелов. Списки временные — их заменят.
- Генерация: случайное слово вида. Если оно свободно, оно и предлагается. Иначе к нему добавляется число 2–99 (до 20 попыток), потом 100–999.
- Если юзернейм уже выбран — `409 Юзернейм уже выбран`.

**`POST /api/me/username`** `{ "username": "барсук" }` → `Me`

| Ответ | Когда |
| --- | --- |
| `409 Юзернейм уже выбран` | у пользователя уже есть юзернейм |
| `400 Такого юзернейма нет среди вариантов — выбери из предложенных` | не подходит под грамматику генератора: слово из любого списка плюс пусто или число 2–999 |
| `409 Этот юзернейм только что заняли — выбери другой` | ключ `username_key` занят |

### Доступ

Все эндпоинты ниже требуют выбранного юзернейма, иначе `409 Сначала выбери юзернейм`. Сначала проверяется вход (`401`), потом юзернейм (`409`).

До выбора юзернейма работают:
- `GET /api/me`;
- `GET /api/usernames/suggestions` и `POST /api/me/username`;
- `POST /api/auth/logout`;
- `POST /api/devices` `{ "token", "env": "sandbox" | "production" }` и `DELETE /api/devices/:token`;
- `GET /api/widget` — до выбора юзернейма всегда отвечает `{ "photo": null }`.

### Друзья

**`GET /api/users/search?q=бар`** → `{ "users": [UserResult] }`

- Запрос нормализуется: trim, нижний регистр, «ё» → «е», ведущий `@` убирается. Короче 2 символов — `{ "users": [] }`.
- Поиск по началу `username_key`, не больше 20 результатов. Точное совпадение идёт первым, остальные — по ключу. Пользователи без юзернейма не ищутся.
- `UserResult = { "id", "username", "relation": "self" | "friend" | "outgoing" | "incoming" | "none" }`.

**`GET /api/friends`** → `Friends`

```json
{
  "friends":  [{ "id": "…", "username": "ярослава", "since": 0, "wishCount": 3, "birthday": "11-14" }],
  "incoming": [{ "id": "…", "username": "енот", "createdAt": 0 }],
  "outgoing": [{ "id": "…", "username": "лось", "createdAt": 0 }]
}
```

`friends` отсортированы по ключу, заявки — сначала новые. `wishCount` — сколько желаний в виш-листе друга, `birthday` — его день рождения или `null`.

**`POST /api/friends/requests`** `{ "userId": "…" }` → `Friends`

- `404 Пользователь не найден` — нет такого пользователя или у него нет юзернейма. `400 Это ты` — заявка самому себе.
- Если вы уже друзья, ничего не меняется.
- Если этот человек сам прислал тебе заявку, вы становитесь друзьями, и ему уходит пуш `friend_accepted`.
- Иначе создаётся заявка (повтор не создаёт вторую), и ему уходит пуш `friend_request` — только если заявка новая.
- Лимит друзей: `409 У тебя уже максимум друзей — 100` или `409 У барсук уже максимум друзей`.

**`POST /api/friends/requests/:userId/accept`** → `Friends`. Без заявки от `userId` — `404 Заявка не найдена`. Создаётся дружба, обе заявки удаляются, автору заявки уходит пуш `friend_accepted`. Лимит такой же.

**`DELETE /api/friends/requests/:userId`** → `Friends`. Отклоняет входящую или отменяет исходящую заявку. Повтор безопасен.

**`DELETE /api/friends/:userId`** → `Friends`. Удаляет дружбу. Повтор безопасен.

### Виш-лист

Что человек хочет получить — на день рождения, праздник или просто так. Свой виш-лист заполняешь сам; виш-лист друга открывается значком-свитком рядом с его именем в списке друзей. Видят его только сам человек и его друзья.

```json
Wish = { "id", "title": "Плёночный фотоаппарат", "url": "https://…" | null, "imageUrl": "https://…/media/….jpg" | null, "createdAt" }
```

**`GET /api/users/:userId/wishes`** → `{ "user": { "id", "username", "birthday" }, "wishes": [Wish] }` — свой или друга, от новых к старым. Чужой — `404 Виш-лист не найден`.

**`POST /api/wishes?title=…&url=…`** (тело — JPEG-картинка или пусто) → `{ "wish": Wish }`.

- `title` — одна строка, пробелы схлопываются, не длиннее 80 символов. Если названия нет, но есть ссылка, название — имя сайта («ozon.ru»). Нет ни того, ни другого — `400 Напиши, что хочешь, или вставь ссылку`.
- `url` — только `http` или `https`, с настоящим доменом (с точкой), без части «логин@» перед адресом (ею маскируют, куда ведёт ссылка). Без схемы спереди добавляется `https://`. Иначе `400 Нужна ссылка на сайт — http:// или https://` или `400 Это не похоже на ссылку`. Длиннее 2048 символов — `400 Слишком длинная ссылка`.
- Картинка — JPEG до 8 МБ, как у фото; другое — `400 Нужна картинка в формате JPEG`.
- Не больше 50 желаний: `409 В виш-листе уже 50 желаний — удали что-нибудь`.
- Сервер ссылки не открывает. Название и картинку по ссылке достаёт телефон (LinkPresentation) и присылает как обычные `title` и тело запроса.

**`DELETE /api/wishes/:id`** → `{ "ok": true }`. Только своё; чужое или удалённое — `404 Желание не найдено`. Картинка удаляется вместе с ним.

### Фото

**`GET /api/photos?before=<ms>&limit=30`** → `{ "photos": [Photo] }`. Лента: твои фото и фото друзей с `created_at < before`, от новых к старым. Закрытые фото тоже приходят — как закрытые карточки.

```json
Photo = {
  "id", "authorId", "authorName", "createdAt", "weekId",
  "locked": false,
  "caption": "…" | null,
  "imageUrl": "https://…/media/….jpg" | null,
  "canReact": true,
  "myStars": 0,
  "mine": []
}
```

- `myStars` (0–3) и `mine` (`creative`, `funny`, `wild`) — только оценка самого зрителя. На своих фото они всегда 0 и `[]`.
- У закрытого фото `locked: true`, `caption` и `imageUrl` равны `null`, `canReact: false`, `myStars: 0`, `mine: []`.
- `canReact` — фото открыто, оно не твоё, и оно этой недели.
- `authorName` — юзернейм.

**`POST /api/photos?caption=…`** (тело — JPEG) → `{ "photo": Photo, "unlocked": 2 }`

- `unlocked` — сколько фото друзей за текущую неделю открылось благодаря этой публикации: по одному от каждого друга, у которого за неделю больше фото, чем было разрешено до неё.
- Каждому другу уходит пуш: `photo`, если новое фото для него открыто, иначе `locked`.

**`GET /api/photos/:id`** → `{ "photo": Photo }`. Только своё фото или фото друга, иначе `404 Фото не найдено`. Закрытое приходит закрытым.

**`DELETE /api/photos/:id`** — только своё, как раньше.

**`PUT|DELETE /api/photos/:id/stars`**, **`PUT|DELETE /api/photos/:id/reactions/:kind`** — как раньше. Оценить можно только открытое фото друга за текущую неделю:

- закрытое — `403 Это фото закрыто — выложи своё, чтобы открыть`;
- своё — `403 Свои фото оценивать нельзя`;
- прошлой недели — `409 Голосование за ту неделю уже закрыто`.

**`GET /api/widget`** → `{ "photo": Photo | null }` — самое новое открытое фото друга.

### Неделя

Итоги считаются для каждого зрителя отдельно. Круг зрителя — он сам и его друзья на сейчас.

- `members` — круг; имя участника — его юзернейм.
- `photos` — фото недели, выложенные кругом. Плюс фото недели, которые оценил кто-то из круга: они нужны только для очков за оценки.
- `reactions` и `stars` — все оценки этих фото.
- Расчёт — `computeStandings` из `awards.js`. Очки внутри него решают, кто друг недели и кто выигрывает ничьи, но наружу не уходят.
- `photoCount` — сколько фото выложил круг.

**`GET /api/week/current`** → превью недели: `{ "weekId", "startsAt", "endsAt", "closedAt": null, "photoCount" }`. Итогов до закрытия нет.
**`GET /api/weeks`** → `{ "weeks": [WeekResults] }` — снимки закрытых недель этого зрителя, от новых, не больше 52.
**`GET /api/weeks/:weekId`** → снимок, или превью текущей недели, или `404 Неделя не найдена`.

```json
WeekResults = {
  "weekId", "startsAt", "endsAt", "closedAt", "photoCount",
  "bestPhoto": Prize | null,
  "mostCreativePost": Prize | null,
  "mostFunnyPost": Prize | null,
  "mostWildPost": Prize | null,
  "postsOfDay": [{ "date": "2026-10-14", "photo": Prize }],
  "friendOfWeek": Winner | null,
  "favoriteFriend": Winner | null,
  "mostCreative": Winner | null,
  "mostFunny": Winner | null,
  "mostWild": Winner | null,
  "mostActive": Winner | null
}
Prize = { "photoId", "authorId", "authorName", "caption", "imageUrl" }
Winner = { "userId", "name" }
```

- `bestPhoto` — пост недели: больше всех звёзд в сумме; при равенстве — больше реакций, потом раньше выложенный. Фото без звёзд не побеждает.
- `mostCreativePost`, `mostFunnyPost`, `mostWildPost` — больше всех ✍️, 😂 или 🫪; при равенстве — больше звёзд, потом раньше выложенный.
- `postsOfDay` — лучший пост каждого дня недели по правилу поста недели; дни по московскому времени, от старых к новым; дни без звёзд пропускаются.
- `friendOfWeek` — больше всех очков. `mostCreative`, `mostFunny`, `mostWild` — больше всех таких реакций на своих фото. `mostActive` — больше всех своих фото и оценок друзьям. `favoriteFriend` — см. «Кто лучше?».
- Ни очков, ни счётчиков, ни таблицы. В снимках недель, закрытых до этого изменения, могут остаться старые поля — приложение их не показывает.

**Закрытие недели.** Каждую закрытую неделю, в которой есть фото, обходят один раз: метка `close:<weekId>` в `jobs` ставится после обхода. Для каждого пользователя с юзернеймом считаются итоги. Если `photoCount > 0`, снимок сохраняется в `weeks(user_id, week_id)`, повтор игнорируется. Если неделя только что закончилась, а снимок новый, уходит пуш `weekly`.

**Напоминание** за `REMINDER_HOURS_BEFORE` часов до конца недели, один раз за неделю (метка `reminder:<weekId>`). Каждому пользователю, у которого есть `unrated` (открытые фото друзей, которые он не оценил) или `locked` (закрытые фото друзей).

### «Кто лучше?»

Раз в день, в случайный момент между `DUEL_FROM_HOUR` и `DUEL_TO_HOUR` (по умолчанию 11:00–21:00 по времени недели), сервер присылает каждому пуш `duel`: двух случайных людей, выбери одного. Если удерживать уведомление, на экране блокировки откроется карточка с двумя людьми. Выбрать можно один раз.

**Пока групп нет, все пользователи приложения — одна компания:** пары берутся из всех, у кого есть юзернейм, кроме самого человека; нужно хотя бы двое других. Дружба здесь не важна. Потом появятся группы — несколько человек, которые пригласили друг друга. Тогда пары и «Самый любимый друг» будут считаться внутри группы. Место для этого — функция `duelPool` в `server/src/app.js`.

- Планирование идёт в `runDue`. Если человек зарегистрировался утром, момент выбирается между «сейчас» и концом окна; после конца окна — на следующий день. Если к моменту отправки кого-то из пары уже нет, сервер выбирает новую пару; если других людей меньше двух, выбор отменяется. Вчерашний выбор после простоя сервера не досылается.
- **`GET /api/duels/today`** → `{ "duel": Duel | null }`. Возвращается только уже отправленный выбор, чтобы случайный момент оставался сюрпризом.
- **`POST /api/duels/:id/choice`** `{ "pick": "left" | "right" }` → `{ "duel": Duel }`. Ошибки:
  - чужой или ещё не отправленный выбор — `404 Выбор не найден`;
  - повторный выбор — `409 Выбор уже сделан`;
  - другое значение `pick` — `400 Выбери левого или правого`.
- `Duel = { "id", "date": "2026-10-23", "left": { "id", "username" }, "right": { "id", "username" }, "choice": "left" | "right" | null }`.
- В итогах недели (`WeekResults.favoriteFriend`) — самый часто выбранный за неделю человек во всём приложении (пока групп нет, он одинаковый у всех): `{ "userId", "name" }`, без числа выборов. При ничьей побеждает тот, чей юзернейм раньше по алфавиту. **Кого выбирали меньше всех, не сообщается нигде**: другие счётчики выборов ни в одном ответе не появляются.

### Оценка дня

«Оцени свой день, как поездку». Каждый вечер (по умолчанию в 23:00, время меняется во вкладке «День») телефон сам показывает уведомление с категорией `DAY_RATING`. Это локальное уведомление, сервер его не шлёт. Если удерживать его, откроется карточка: 1–5 звёзд, ниже — что помешало дню стать твоим (меньше 5) или что понравилось больше всего (5), и два вопроса «да/нет». Оценки видит только их автор.

**`PUT /api/days/:date`** — `date` в виде `2026-10-23`, это день по календарю телефона.

```json
{ "stars": 4, "reasons": ["fatigued", "gps"], "liked": [], "condition": true, "place": null }
```

→ `{ "day": Day }`. Повторный запрос заменяет оценку.

- `stars` — от 1 до 5, иначе `400 Звёзд может быть от 1 до 5`.
- `reasons` учитываются только при `stars < 5`, `liked` — только при `stars = 5`. Порядок берётся из списков ниже, повторы убираются. Неизвестный id — `400 Неизвестный вариант оценки`.
- `condition` («В хорошей форме?») и `place` («В хорошем месте?») — `true`, `false` или `null`.
- Дата — настоящая, от двух месяцев назад до завтра (часовые пояса), иначе `400 Неверная дата` / `400 Эту дату оценить нельзя`.

**`GET /api/days?limit=30`** → `{ "days": [Day] }`, сначала новые, не больше 120.

`Day = { "date", "stars", "reasons": [id], "liked": [id], "condition": bool|null, "place": bool|null, "updatedAt": ms }`.

| `reasons` — что помешало | | `liked` — что понравилось | |
| --- | --- | --- | --- |
| `unchanged` | Ничего не поменялось | `advice` | Полезный совет |
| `distracted` | Всё отвлекало | `polite` | Вежливые люди |
| `awkward` | Было неловко | `comfort` | Зона комфорта |
| `odor` | Сильный запах | `clean` | Чистый салон |
| `issues` | Проблемы с бла-бла-бла | `conversation` | Хороший разговор |
| `reckless` | Безрассудство | `music` | Приятная музыка |
| `noChance` | Не было шанса | | |
| `fatigued` | Усталость | | |
| `gps` | Ошибка GPS: место — отстой | | |
| `rude` | Грубые люди | | |

Русские подписи — в `ios/Shared/DayRating.swift`; ids — в `server/src/app.js` (`DAY_REASONS`, `DAY_HIGHLIGHTS`).

**Приложение:**

- Категория `FRIEND_REQUEST` с кнопкой `ACCEPT_FRIEND` «Принять» — заявку можно принять прямо с экрана блокировки, приложение отправит запрос в фоне.
- Нажатие на `locked` открывает камеру. Нажатие на `friend_request` или `friend_accepted` открывает «Друзья».
- Категория `BIRTHDAY` с кнопкой `OPEN_WISHLIST` «Открыть виш-лист». Она и нажатие на `birthday` открывают виш-лист `userId` поверх любой вкладки.

## База (`user_version = 4`)

```sql
users(id TEXT PRIMARY KEY, username TEXT, username_key TEXT UNIQUE, password_key TEXT NOT NULL UNIQUE, created_at INTEGER NOT NULL)
sessions(token_hash TEXT PRIMARY KEY, user_id → users ON DELETE CASCADE, created_at)
devices(token TEXT PRIMARY KEY, user_id → users ON DELETE CASCADE, env, updated_at)
friend_requests(from_id → users, to_id → users, created_at, PRIMARY KEY(from_id, to_id))
friendships(user_a → users, user_b → users, created_at, PRIMARY KEY(user_a, user_b), CHECK(user_a < user_b))
photos(id TEXT PRIMARY KEY, author_id → users, week_id, caption, file, created_at)
  -- индексы: (author_id, week_id, created_at), (created_at)
reactions, stars, jobs — как раньше
weeks(user_id → users ON DELETE CASCADE, week_id, closed_at, results, PRIMARY KEY(user_id, week_id))
days(user_id → users ON DELETE CASCADE, date, stars 1–5, reasons JSON, liked JSON, condition, place, updated_at, PRIMARY KEY(user_id, date))
duels(id PRIMARY KEY, user_id, date, left_id, right_id, send_at, sent_at, choice, chosen_id, week_id, chosen_at, UNIQUE(user_id, date))
wishes(id PRIMARY KEY, user_id → users ON DELETE CASCADE, title, url, file, created_at)
birthdays(user_id PRIMARY KEY → users ON DELETE CASCADE, month 1–12, day 1–31, asked_later_at, updated_at)
  -- индекс: (user_id, created_at)
```

Версии 3 и 4 только добавляют таблицы `wishes` и `birthdays`: база версии 2 или 3 открывается как есть, новые таблицы создаются рядом.

**Старая база.** Если версия файла меньше текущей и в нём есть таблица `circles`, это база первой версии с компаниями и email. Её файл (и `-wal`, `-shm`) переименовывается в `locket.v1-<время>.db`, а рядом создаётся новая. Старые данные не удаляются, но и не используются.

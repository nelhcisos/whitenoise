# Locket API

Контракт между сервером (`server/`) и iPhone-приложением (`ios/`). Сервер — источник правды. Если меняешь здесь — меняй и там.

- База — `PUBLIC_URL`. JSON в UTF-8. Время — миллисекунды с 1970 года (число).
- Авторизация: `Authorization: Bearer <token>`.
- Ошибка — HTTP-статус и `{ "error": "<по-русски: что случилось и что делать>" }`. Приложение показывает этот текст как есть.

## Модель

**Аккаунт = пароль.** Логина нет. Пароль, который уже есть, впускает в свой аккаунт. Новый пароль создаёт новый аккаунт — но только вместе с первым фото.

- Пароль: от 4 до 64 символов после нормализации NFC; пробелы не обрезаются. Длина считается в символах (`[...password].length`).
- Сервер хранит `password_key = HMAC-SHA256(pepper, NFC(password))` в hex с уникальным индексом: поиск идёт по паролю, а утёкшая база без pepper бесполезна.
- Pepper берётся из `PASSWORD_PEPPER`, а если переменной нет — из файла `<DATA_DIR>/pepper`. Файл создаётся при первом запуске: 32 случайных байта в hex. **Без pepper никто не войдёт.** Он лежит в папке данных и бэкапится вместе с базой.
- Юзернейм вписать нельзя — его выбирают из трёх предложений сервера. До выбора `username = null`. Юзернейм уникален по ключу `username_key`: нижний регистр и «ё» → «е». В этой версии сменить его нельзя.
- Друзья: заявка, потом принятие. Дружба взаимная, максимум `MAX_FRIENDS` (100).
- Неделя та же: закрывается в воскресенье в 21:00 по Москве (`week.js`).

### Закрытые фото

Для зрителя V, друга A и недели W:

```
allowance(V, W) = 1 + (сколько фото V выложил за неделю W)
```

Фото A за неделю W сортируются по `(created_at, rowid)` по возрастанию. Фото с индексом `i` (с нуля) открыто для V, если `i < allowance(V, W)`.

- Первое фото друга за неделю видно всегда. Каждое твоё фото за эту неделю открывает тебе ещё по одному фото **каждого** друга за ту же неделю.
- Свои фото открыты всегда.
- Правило действует и для прошлых недель: счёт остаётся таким, каким был в ту неделю.
- Закрытое фото приходит без содержимого (см. `Photo`). Его нельзя оценить (403), оно не попадает в виджет, и пуш о нём приходит без картинки.
- Исключение — «Фото недели» в итогах: его картинка видна всем, кто видит итоги, потому что это приз.

## Эндпоинты

### Вход

**`POST /api/auth/password`** — без авторизации.

```json
{ "password": "..." }
```

| Ответ | Когда |
| --- | --- |
| `200 { "status": "signedIn", "token": "...", ...Me }` | такой пароль есть: вход |
| `200 { "status": "new" }` | такого пароля нет; аккаунт **не** создаётся |
| `400 Пароль — минимум 4 символа` / `Пароль — не длиннее 64 символов` | |
| `429 Слишком много попыток — подожди 10 минут` | 20 ответов `new` за 10 минут с одного IP |

IP: при `TRUST_PROXY=1` (так за Caddy) берётся первый адрес из `X-Forwarded-For`, иначе — адрес сокета.

**`POST /api/auth/register`** — без авторизации, JSON до 12 МБ.

```json
{ "password": "...", "photo": "<JPEG в base64>", "caption": "необязательно, до 60 символов" }
```

- Пароль проверяется так же. Фото — JPEG (`FF D8 FF`) не больше 8 МБ после декодирования; иначе `400 Нужна картинка в формате JPEG` или `413 Слишком большой файл`.
- Если такой пароль уже есть (кто-то успел раньше), это вход: фото публикуется в тот аккаунт как обычное. Ответ: `200 { "status": "signedIn", "token", ...Me }`.
- Иначе в одной транзакции создаются пользователь (`username = null`) и его фото. Ответ: `200 { "status": "created", "token", ...Me }`.
- Не больше 10 новых аккаунтов в час с одного IP, иначе `429 Слишком много новых аккаунтов — попробуй через час`.

**`POST /api/auth/logout`** — как раньше: `{ "deviceToken"?: "..." }` → `{ "ok": true }`.

### Профиль и юзернейм

**`GET /api/me`** → `Me`

```json
{
  "user": { "id": "…", "username": "барсук" },
  "friends": [{ "id": "…", "username": "ярослава" }],
  "incomingRequests": 1,
  "week": { "id": "2026-W42", "startsAt": 0, "endsAt": 0 }
}
```

`username` равен `null`, пока юзернейм не выбран. Друзья отсортированы по `username_key`.

**`GET /api/usernames/suggestions`** → ровно три свободных варианта, по одному каждого вида:

```json
{ "suggestions": [
  { "username": "барсук", "kind": "animal" },
  { "username": "мудила7", "kind": "swear" },
  { "username": "ярослава", "kind": "name" }
] }
```

- Слова лежат в `server/src/usernames.js`: `USERNAME_WORDS = { animal: [...], swear: [...], name: [...] }`. Все слова в нижнем регистре, кириллицей, без пробелов. Списки временные — их заменят.
- Генерация: случайное слово вида. Если оно свободно, оно и предлагается. Иначе к нему добавляется число 2–99 (до 20 попыток), потом 100–999.
- Если юзернейм уже выбран — `409 Юзернейм уже выбран`.

**`POST /api/me/username`** `{ "username": "барсук" }` → `Me`

| Ответ | Когда |
| --- | --- |
| `409 Юзернейм уже выбран` | у пользователя уже есть юзернейм |
| `400 Такого юзернейма нет среди вариантов — выбери из предложенных` | не подходит под грамматику генератора: слово из любого списка плюс пусто или число 2–999 |
| `409 Этот юзернейм только что заняли — выбери другой` | ключ `username_key` занят |

### Доступ

Все эндпоинты ниже требуют выбранного юзернейма, иначе `409 Сначала выбери юзернейм`. Сначала проверяется вход (`401`), потом юзернейм (`409`).

До выбора юзернейма работают:
- `GET /api/me`;
- `GET /api/usernames/suggestions` и `POST /api/me/username`;
- `POST /api/auth/logout`;
- `POST /api/devices` `{ "token", "env": "sandbox" | "production" }` и `DELETE /api/devices/:token`;
- `GET /api/widget` — до выбора юзернейма всегда отвечает `{ "photo": null }`.

### Друзья

**`GET /api/users/search?q=бар`** → `{ "users": [UserResult] }`

- Запрос нормализуется: trim, нижний регистр, «ё» → «е», ведущий `@` убирается. Короче 2 символов — `{ "users": [] }`.
- Поиск по началу `username_key`, не больше 20 результатов. Точное совпадение идёт первым, остальные — по ключу. Пользователи без юзернейма не ищутся.
- `UserResult = { "id", "username", "relation": "self" | "friend" | "outgoing" | "incoming" | "none" }`.

**`GET /api/friends`** → `Friends`

```json
{
  "friends":  [{ "id": "…", "username": "ярослава", "since": 0 }],
  "incoming": [{ "id": "…", "username": "енот", "createdAt": 0 }],
  "outgoing": [{ "id": "…", "username": "лось", "createdAt": 0 }]
}
```

`friends` отсортированы по ключу, заявки — сначала новые.

**`POST /api/friends/requests`** `{ "userId": "…" }` → `Friends`

- `404 Пользователь не найден` — нет такого пользователя или у него нет юзернейма. `400 Это ты` — заявка самому себе.
- Если вы уже друзья, ничего не меняется.
- Если этот человек сам прислал тебе заявку, вы становитесь друзьями, и ему уходит пуш `friend_accepted`.
- Иначе создаётся заявка (повтор не создаёт вторую), и ему уходит пуш `friend_request` — только если заявка новая.
- Лимит друзей: `409 У тебя уже максимум друзей — 100` или `409 У барсук уже максимум друзей`.

**`POST /api/friends/requests/:userId/accept`** → `Friends`. Без заявки от `userId` — `404 Заявка не найдена`. Создаётся дружба, обе заявки удаляются, автору заявки уходит пуш `friend_accepted`. Лимит такой же.

**`DELETE /api/friends/requests/:userId`** → `Friends`. Отклоняет входящую или отменяет исходящую заявку. Повтор безопасен.

**`DELETE /api/friends/:userId`** → `Friends`. Удаляет дружбу. Повтор безопасен.

### Фото

**`GET /api/photos?before=<ms>&limit=30`** → `{ "photos": [Photo] }`. Лента: твои фото и фото друзей с `created_at < before`, от новых к старым. Закрытые фото тоже приходят — как закрытые карточки.

```json
Photo = {
  "id", "authorId", "authorName", "createdAt", "weekId",
  "locked": false,
  "caption": "…" | null,
  "imageUrl": "https://…/media/….jpg" | null,
  "canReact": true,
  "counts": { "creative": 0, "funny": 0, "wild": 0 },
  "stars": { "count": 0, "total": 0, "average": 0 },
  "myStars": 0, "mine": [], "reactors": [], "raters": []
}
```

- У закрытого фото `locked: true`, `caption` и `imageUrl` равны `null`, `canReact: false`, счётчики нулевые, списки пустые.
- `canReact` — фото открыто, оно не твоё, и оно этой недели.
- `authorName`, `reactors[].name` и `raters[].name` — это юзернеймы.

**`POST /api/photos?caption=…`** (тело — JPEG) → `{ "photo": Photo, "unlocked": 2 }`

- `unlocked` — сколько фото друзей за текущую неделю открылось благодаря этой публикации: по одному от каждого друга, у которого за неделю больше фото, чем было разрешено до неё.
- Каждому другу уходит пуш: `photo`, если новое фото для него открыто, иначе `locked`.

**`GET /api/photos/:id`** → `{ "photo": Photo }`. Только своё фото или фото друга, иначе `404 Фото не найдено`. Закрытое приходит закрытым.

**`DELETE /api/photos/:id`** — только своё, как раньше.

**`PUT|DELETE /api/photos/:id/stars`**, **`PUT|DELETE /api/photos/:id/reactions/:kind`** — как раньше. Оценить можно только открытое фото друга за текущую неделю:

- закрытое — `403 Это фото закрыто — выложи своё, чтобы открыть`;
- своё — `403 Свои фото оценивать нельзя`;
- прошлой недели — `409 Голосование за ту неделю уже закрыто`.

**`GET /api/widget`** → `{ "photo": Photo | null }` — самое новое открытое фото друга.

### Неделя

Итоги считаются для каждого зрителя отдельно. Круг зрителя — он сам и его друзья на сейчас.

- `members` — круг; имя участника — его юзернейм.
- `photos` — фото недели, выложенные кругом. Плюс фото недели, которые оценил кто-то из круга: они нужны только для очков за оценки.
- `reactions` и `stars` — все оценки этих фото.
- Расчёт — `computeStandings` из `awards.js`, без изменений. Каждый человек получает одни и те же очки у любого зрителя.
- `leaderboard` — все участники круга. `photoCount` — сколько фото выложил круг. `bestPhoto` — лучшее фото круга, картинка видна всегда.

**`GET /api/week/current`** → `WeekResults` (живые).
**`GET /api/weeks`** → `{ "weeks": [WeekResults] }` — снимки закрытых недель этого зрителя, от новых, не больше 52.
**`GET /api/weeks/:weekId`** → снимок, или живые итоги текущей недели, или `404 Неделя не найдена`.

Форма `WeekResults` прежняя: `weekId`, `startsAt`, `endsAt`, `closedAt`, `photoCount`, `leaderboard`, `bestPhoto`, `friendOfWeek`, `mostCreative`, `mostFunny`, `mostWild`, `mostActive`.

**Закрытие недели.** Каждую закрытую неделю, в которой есть фото, обходят один раз: метка `close:<weekId>` в `jobs` ставится после обхода. Для каждого пользователя с юзернеймом считаются итоги. Если `photoCount > 0`, снимок сохраняется в `weeks(user_id, week_id)`, повтор игнорируется. Если неделя только что закончилась, а снимок новый, уходит пуш `weekly`.

**Напоминание** за `REMINDER_HOURS_BEFORE` часов до конца недели, один раз за неделю (метка `reminder:<weekId>`). Каждому пользователю, у которого есть `unrated` (открытые фото друзей, которые он не оценил) или `locked` (закрытые фото друзей).

## Пуши

| `type` | Кому | `aps` | Остальные поля |
| --- | --- | --- | --- |
| `photo` | другу, для которого новое фото открыто | как раньше: `category: PHOTO_RATING`, `mutable-content: 1`, title — юзернейм автора | `photoId`, `authorId`, `authorName`, `caption`, `imageUrl`, `createdAt` |
| `locked` | другу, для которого новое фото закрыто | title — юзернейм автора, body «Новое фото закрыто — выложи своё, и оно откроется», `thread-id: photos`, **без** картинки и `mutable-content` | `photoId` |
| `reaction` | автору фото | как раньше; title — юзернейм того, кто оценил | `photoId`, `imageUrl` |
| `friend_request` | тому, кому пришла заявка | title «Заявка в друзья», body «барсук хочет дружить», `category: FRIEND_REQUEST`, `thread-id: friends` | `userId` — кто зовёт |
| `friend_accepted` | автору заявки | title «Новый друг», body «ярослава теперь в друзьях», `thread-id: friends` | `userId` |
| `weekly` | каждому, у кого есть снимок | как раньше, итоги его круга | `weekId`, `imageUrl` |
| `reminder` | см. выше | title «До итогов недели 3 ч». Body: «2 фото ждут твоей оценки — успей до итогов»; если есть закрытые, добавляется « · ещё 3 закрыты — выложи своё». Если ждущих оценки нет: «3 фото друзей закрыты — выложи своё, чтобы открыть» | |

Число и слово в пушах склеены неразрывным пробелом.

**Приложение:**

- Категория `FRIEND_REQUEST` с кнопкой `ACCEPT_FRIEND` «Принять» — заявку можно принять прямо с экрана блокировки, приложение отправит запрос в фоне.
- Нажатие на `locked` открывает камеру. Нажатие на `friend_request` или `friend_accepted` открывает «Друзья».

## База (`user_version = 2`)

```sql
users(id TEXT PRIMARY KEY, username TEXT, username_key TEXT UNIQUE, password_key TEXT NOT NULL UNIQUE, created_at INTEGER NOT NULL)
sessions(token_hash TEXT PRIMARY KEY, user_id → users ON DELETE CASCADE, created_at)
devices(token TEXT PRIMARY KEY, user_id → users ON DELETE CASCADE, env, updated_at)
friend_requests(from_id → users, to_id → users, created_at, PRIMARY KEY(from_id, to_id))
friendships(user_a → users, user_b → users, created_at, PRIMARY KEY(user_a, user_b), CHECK(user_a < user_b))
photos(id TEXT PRIMARY KEY, author_id → users, week_id, caption, file, created_at)
  -- индексы: (author_id, week_id, created_at), (created_at)
reactions, stars, jobs — как раньше
weeks(user_id → users ON DELETE CASCADE, week_id, closed_at, results, PRIMARY KEY(user_id, week_id))
```

**Старая база.** Если в файле нет `user_version = 2`, но есть таблица `circles`, это база первой версии с компаниями и email. Её файл (и `-wal`, `-shm`) переименовывается в `locket.v1-<время>.db`, а рядом создаётся новая. Старые данные не удаляются, но и не используются.

| Переменная | По умолчанию | Что |
| --- | --- | --- |
| `PASSWORD_PEPPER` | файл `<DATA_DIR>/pepper` | секрет для `password_key` |

| `PORT`, `PUBLIC_URL`, `DATA_DIR`, `TZ_OFFSET_MINUTES`, `WEEK_END_DAY`, `WEEK_END_HOUR`, `REMINDER_HOURS_BEFORE`, `APNS_*` | как раньше | |

`MAX_CIRCLE_MEMBERS` больше не нужна.

# Дизайн Locket

Два источника, по ним принимается каждое решение:

1. **taste-skill v2** (`npx skills add Leonxlnx/taste-skill`), глава `references/app-screens.md` — правила для экранов, в которых работают (наш случай), тёмная тема.
2. **Vercel Web Interface Guidelines** (vercel.com/design/guidelines) — взаимодействия, состояния, формы, текст, доступность. Веб-правила переведены на iOS: «focus ring» → VoiceOver и Dynamic Type, «aria-label» → `accessibilityLabel`, «prefers-reduced-motion» → `accessibilityReduceMotion`.

Токены — в `Shared/Theme.swift`, общие компоненты — в `Locket/Components/Components.swift`. Экран собирается только из них; свои цвета, радиусы и шрифты в экранах не заводятся.

## 1. Токены

| Роль | Значение | Где |
| --- | --- | --- |
| `Palette.ground` | #000 | фон экрана |
| `Palette.surface` | #111 | карточки, поля, чипы — шаг тона над фоном |
| `Palette.raised` | #222 | вложенные поверхности, скелетоны, тост |
| `Palette.border` | #2e2e2e | линии на поверхности, рамка поля |
| `Palette.control` | #444 | обводка вторичной кнопки |
| `Palette.text` / `muted` / `faint` | #fff / #b4b4b4 / #949494 | текст: основной / вторичный / мета и плейсхолдеры (все ≥ 4.5:1 на чёрном) |
| `Palette.accent` | жёлтый Locket | **только данные** (звёзды, твои реакции, лидер недели, фото недели) и **не больше одного элемента управления на экран** (кнопка «Отправить» на камере) |
| `Palette.accentTint` | accent 20 % | заливка выбранной реакции или звезды — всегда вместе с обводкой accent 1,5 pt; одинаково в ленте, уведомлении и виджете |
| `Palette.systemFill` | primary 8 % | заливки на системном материале окна уведомления (оно бывает светлым) |
| `Palette.positive` / `negative` | #3fc07a / #e5566f | статусы и ошибки, всегда вместе с текстом или иконкой |
| `Radius.photo` / `card` / `control` / `line` | 24 / 20 / 14 / 6 | вложенные радиусы уменьшаются; чипы — капсула; `line` — скелетон строки текста |
| `Space.margin` / `gap` / `cardPadding` / `section` | 20 / 16 / 20 / 40 | одно поле по бокам, один зазор по горизонтали и вертикали |
| `Space.header` | 12 | от заголовка секции до её содержимого — на всех экранах одинаково |
| `AvatarSize.small` / `regular` | 32 / 40 | только два размера аватара: строки и стопки — `small`, своя строка профиля — `regular` |
| `Space.controlHeight` / `hitTarget` | 50 / 44 | высота кнопок и полей; минимальная зона нажатия |

**Шрифт** — один гротеск (SF Pro), только системные стили, чтобы работал Dynamic Type. Не больше пяти размеров на экран: `.title` 28 (заголовок экрана, bold) · `.title3` 20 (заголовок секции, semibold; цифра-ответ экрана) · `.body` 17 · `.subheadline` 15 · `.footnote` 13. Инициал в аватаре тоже из этой шкалы (`.footnote` или `.body`). Начертаний три: regular, semibold, bold (bold — только заголовок экрана). Все числа — `.monospacedDigit()`; у `ScreenTitle` и `SectionHeader` это уже включено. Скруглённый шрифт — только словесный знак `Wordmark`.

## 2. Правила

Делаем:
- Цвет — на данных, не на интерфейсе. Глобальный `tint` белый. Выбранная вкладка выделяется яркостью, а не цветом.
- Поверхности разделяются шагом тона (#000 → #111 → #222). Не тенью и не рамкой; рамка — только у полей и вторичных кнопок.
- Панель вкладок и навигационная панель непрозрачные, цвета фона (`.groundBar(for:)`): под прокрученным контентом не появляется системное размытие. Экран без навигационной панели закрывает статус-бар полосой фона.
- У каждого экрана один `ScreenTitle` — существительное, а не приветствие. Вторая строка — одна фраза о данных: находка или период.
- Самое крупное на экране отвечает на главный вопрос экрана (см. §4).
- Числа: табличные цифры; число и единица склеены неразрывным пробелом (`nbsp`): «3 фото», «2 дня», «21:00». Ноль печатается нулём, отсутствие — серым «—».
- Порядок показывается позицией или настоящим рангом «1», «2», «3» (ранг — это данные).
- Иконки — SF Symbols в контурном варианте, серые, рядом с подписью или одной кнопкой (закрыть, ещё, назад). У иконки-кнопки обязательно `accessibilityLabel`.

Не делаем (запрещено обоими источниками):
- **Эмодзи как украшение** в заголовках, подписях, кнопках, пустых состояниях, тостах: 🏆 👑 📸 ⚡️ 🥇 👋 💛 ⏰ 🗳 и т. п. Исключение — шкала оценок ✍️ 😂 🫪: её выбрали пользователи, это данные, знак вида реакции.
- Градиенты, «стекло» (`.ultraThinMaterial` и другие материалы), свечения, тени у предметов в покое.
- Капс и разрядка в подписях; маленькие подписи над заголовком.
- Плитки с иконкой или эмодзи сверху, сетки одинаковых карточек ради сетки — группа фактов становится одним списком строк.
- Модальный `alert` для ошибок загрузки — ошибка показывается внутри блока, который не загрузился (`InlineError` с «Повторить»), в том числе при подгрузке старых фото. Фоновая загрузка никогда не показывает тост. Тост `model.show(error:)` — только для действия, которое человек начал сам. Ошибка формы — под её полем, а не тостом и не в `alert`.
- Поле ввода внутри `alert`: правка имени и названия — отдельный лист с `FormField`.
- Спиннер на месте контента — вместо него скелетон реального размера (`SkeletonBlock` + `.appearsAfter()`). При запуске — словесный знак, а через секунду строка «Подключаюсь к серверу…».
- Анимации появления. Движение — только отклик на действие (нажатие, выбор, появление листа) и уважает «Уменьшение движения».

## 3. Компоненты (`Components.swift`)

| Компонент | Когда |
| --- | --- |
| `ScreenTitle(title:subtitle:)` | первая строка каждого экрана |
| `SectionHeader("…")` / `SectionHeader(title:) { trailing }` | заголовок секции, справа — текстовое действие |
| `Card { }` | группа строк на поверхности #111 |
| `LocketButtonStyle(.primary / .accent / .secondary / .destructive)` | `.primary` — белая заливка, одна на экран; `.accent` — жёлтая, только «Отправить» на камере; `.secondary` — обводка; `.destructive` — обводка, красный текст |
| `ButtonLabel(title:isLoading:)` | подпись остаётся во время запроса, спиннер слева |
| `FormField(label:error:) { TextField }` | подпись над полем, ошибка под полем (её же читает VoiceOver); плейсхолдер — пример значения («Например, masha@mail.ru») или подсказка с «…» («Подпись…») |
| `InlineError(message:retry:)` | блок не загрузился |
| `EmptyState(text:actionTitle:action:)` | пустой блок: рамка, одна фраза, следующий шаг |
| `SkeletonBlock(height:)` + `.appearsAfter()` | загрузка: серые плашки реального размера, появляются только если ждать больше 250 мс |
| `Avatar(name:size:)` | человек: инициал на приглушённом тоне его собственного цвета; размер `AvatarSize.small` или `.regular` |
| `Wordmark()` | словесный знак «Locket»: вход, запуск |
| `SquarePhoto(url:)` / `RemoteImage(url:)` | фото; загрузка — ровная серая плашка |

## 4. Экраны: вопрос, находка, порядок

**Вход** (`AuthView`, `FirstPhotoView`, `UsernamePickerView`). Вопрос: «как начать?».
- *Пароль.* Словесный знак Locket (без жёлтой плитки — акцент не украшение) и одна фраза. Одно поле «Пароль» с кнопкой «Показать пароль», под ним серая строка «Логина нет: пароль и есть аккаунт…». Кнопка «Войти» не блокируется заранее: короткий пароль — ошибка под полем.
- *Новый аккаунт.* Если такого пароля нет, это камера с заголовком «Новый аккаунт». Введённый пароль показан моноширинным чипом — чтобы опечатку заметили сейчас, а не при следующем входе. Рядом кнопка «Другой пароль». Фото публикуется сразу.
- *Юзернейм.* Три строки на `Card`: юзернейм крупно и серое слово вида справа («животное», «мат», «имя»). Выбор — иконка `checkmark.circle.fill` плюс трейт `.isSelected`, без жёлтого: это элемент управления, а не данные. Кнопка «Выбрать «барсук»» и вторичная «Другие варианты». Вписать свой юзернейм нельзя.

**Камера** (`CameraScreen`). Вопрос: «что отправить?». Самое крупное — видоискатель. Сверху «Камера» и «Увидят: 3 друга». После отправки тост говорит, сколько фото друзей открылось. Жёлтая кнопка — только «Отправить»; во время отправки иконка остаётся, под кнопками строка «Отправляю…». Затвор — белое кольцо. Ошибка отправки показывается под кнопками, фото не теряется. У всех круглых кнопок подписи для VoiceOver: «Вспышка», «Сменить камеру», «Выбрать из галереи», «Сделать фото», «Отменить», «Отправить друзьям».

**Лента** (`FeedView`). Вопрос: «что выложили друзья?». Находка во второй строке заголовка: «3 фото ждут твоей оценки · 2 закрыты» или «Ты оценил все фото этой недели». Фото — главный элемент. Закрытое фото — карточка того же размера: поверхность #111, серый замок, «Закрыто», «Выложи своё фото — и откроется ещё одно», кнопка «Открыть камеру»; без звёзд. Под открытым фото звёзды 1–3 (44 pt) и реакции ✍️ 😂 🫪. Твой выбор — жёлтым, плюс трейт `.isSelected` (только на той звезде, которую поставил ты), плюс форма (заполненная звезда, обводка у реакции), а не только цвет. Оценки вслепую: у реакций нет чисел, под фото нет строки «кто что поставил». Под своим фото вместо звёзд — серая строка с `eye.slash`: «Оценки друзей — секрет. Победителей объявим в воскресенье». Бейдж на вкладке «Лента» прячется, пока лента открыта: число уже есть в заголовке. Состояния: скелетон из двух карточек; ошибка с «Повторить»; пусто — фраза и кнопка «Открыть камеру».

**Неделя** (`WeekView`, `WeekResultsView`). Вопрос: «сколько до итогов?». Под заголовком «Итоги в воскресенье в 21:00 · через 2 дня». Первый блок — карточка «Пока секрет» (`eye.slash`): «Победителей назовём в воскресенье в 21:00», почему ничего не видно (звёзды и реакции не видит никто) и «11 фото у тебя и друзей на этой неделе». Ни лидера, ни очков, ни таблицы. Дальше прошлые недели и «Как выбираем победителей». Пустая неделя: фраза и «Сделать фото»; без друзей — «Победителей выбирают среди друзей…» и «Найти друзей».

*Итоги недели* — только победители, без цифр: «Друг недели» (аватар и имя жёлтым), «Пост недели» (фото, автор, подпись), «Посты дня» (ряд квадратов, листается вбок: день недели и автор), «Лучшие посты» (миниатюра 48 pt, «✍️ Самый креативный пост», автор) и «Номинации» («Самый любимый друг», «✍️ Самый креативный друг»…, «Самый активный»). Нет победителя — серое «—». VoiceOver читает реакции словами (`ReactionKind.title`), а не эмодзи: у 🫪 нет озвучки в старых iOS.

**Друзья** (`FriendsView`). Вопрос: «как найти друзей?». Сверху твой юзернейм (`.title3`) и «Поделиться юзернеймом…». Поиск по юзернейму — поле с подписью над ним; у каждого результата одно действие по его статусу: «Добавить», «Принять», серое «Заявка отправлена» с «Отменить», серое «В друзьях». Под юзернеймом — «Мой виш-лист» (значок `scroll`) и «День рождения — 14 ноября» / «Указать день рождения» (`birthday.cake`). Под именем друга серым: «День рождения через 5 дней» (в пределах месяца), «Сегодня день рождения 🎂», иначе «День рождения 14 ноября». Ниже входящие заявки («Принять» / «Отклонить»), отправленные, список друзей: справа у каждого свиток `scroll` с числом желаний (44 pt; серый, если пусто) и «Удалить из друзей…» в меню «…» (с подтверждением), уведомления. Последней — кнопка «Выйти» (`.destructive`) с предупреждением, что вернуться можно только по паролю.

**Виш-лист** (`Features/Wishlist/WishlistView`). Лист снизу. Вопрос: «что ему подарить?». Заголовок «Виш-лист», ниже «ёжик · 3 желания» (свой — «Мой виш-лист» и «друзья видят его рядом с твоим именем»). Плитки в две колонки (одна на самых крупных размерах текста): квадратная картинка, без неё — серый `gift` или `link`; название до трёх строк; сайт серым со стрелкой `arrow.up.right`. Плитка со ссылкой открывает её в браузере. На своих плитках — круглое «…» поверх картинки с «Удалить…» и подтверждением. Свой список: белая кнопка «Добавить желание» — одна главная на экране. Пусто у себя — фраза, что добавить и кто увидит; пусто у друга — «Здесь пока пусто». Скелетон — четыре плитки.

*Новое желание* — лист поверх: «Ссылка» (системная кнопка «Вставить» без запроса доступа к буферу), строка статуса под ней («Название и картинка подтянутся по ссылке сами», «Ищу название и картинку…», «Готово — поправь, если нужно»), «Что хочешь», «Картинка» (из галереи, «Другая» / «Убрать»), белая «Добавить». Название по ссылке заменяет только то, что ты ещё не правил. Хватает названия или ссылки.

**День рождения** (`Features/Birthday/BirthdayView`). После третьего своего фото вверху ленты карточка «Когда у тебя день рождения?» с объяснением, кому и когда придёт напоминание, кнопками «Указать дату» и «Не сейчас» (вернётся через месяц). Выбор — лист с двумя колёсами: день и месяц в родительном падеже («14 ноября»), год не спрашиваем; белая «Сохранить», красная «Убрать дату», если дата уже есть. Пуш о дне рождения друга и кнопка «Открыть виш-лист» открывают его виш-лист листом поверх любой вкладки; в подзаголовке виш-листа — «День рождения через 5 дней».

**Кто лучше?** (`Shared/Duel.swift` → `DuelChoiceView`, `NotificationContent/DuelCard`, `DuelPrompt` в ленте). Вопрос: «кто из двоих?». Две равные плитки рядом: инициал в круге и юзернейм, высота от 132 pt. Выбранная — `accentTint` + обводка, вторая бледнеет; после выбора нажать нельзя. Подзаголовок «Выбери одного — кого не выбрал, никто не узнает». В ленте карточка висит сверху, пока не выберешь; в итогах недели — строка «Самый любимый друг» первой в номинациях. Кого выбирали меньше всех, не показывается нигде. Пока групп нет, пары и итоги — среди всех пользователей приложения.

**День** (`DayView`, `Shared/DayRatingForm`, `NotificationContent/DayRatingCard`). Вопрос: «как прошёл день?». Пять звёзд (44 pt, жёлтые — данные). Меньше пяти — «Что помешало дню стать твоим?», пять — «Что понравилось больше всего?»: чипы-капсулы, выбранный — `accentTint` + обводка. Два вопроса «В хорошей форме?» / «В хорошем месте?» с «Нет» / «Да»; повторное нажатие снимает ответ. После трёх и меньше — «Завтра попробуй: разминка · медитация · холодный душ». Сохраняется само через полсекунды после нажатия, строка статуса под формой. Ниже — «Вчера», «Решения», «Последние дни» (звёзды и причины), «Напоминание» со временем и «Проверить уведомление». На экране блокировки — та же форма на системном материале.

**Окно уведомления** (`NotificationContent/RatingCard`) и **виджет**: те же звёзды и реакции, тот же язык. Статус под кнопками без эмодзи: «Поставь оценку — приложение открывать не нужно», «Сохраняю…», «Оценка сохранена», ошибка с подсказкой, что делать («Попробуй ещё раз» — только когда повтор поможет; без входа — «Открой Locket и войди…»). Кнопки виджета — не ниже 44 pt; виджет без входа и пустой виджет различаются и по нажатию открывают приложение.

## 5. Текст

- Второе лицо на «ты», действительный залог, глагол на кнопке называет действие: «Войти», «Отправить», «Принять», а не «Продолжить» или «ОК».
- Пункт, который открывает следующий шаг (лист, подтверждение), заканчивается многоточием: «Изменить имя…», «Удалить фото…», «Поделиться кодом…».
- Состояния процесса тоже с многоточием: «Отправляю…», «Сохраняю…». Многоточие — один символ «…».
- Кавычки «ёлочки». Числа цифрами. Число и единица — через неразрывный пробел.
- Ошибка говорит, что делать дальше: «Не удалось загрузить ленту. Проверь интернет и нажми „Повторить“».

## 6. Доступность и движение

- Зона нажатия не меньше 44×44. Иконки-кнопки подписаны. Декоративное скрыто (`accessibilityHidden`). У заголовков трейт `.isHeader`.
- Статус не передаётся только цветом: у ошибок есть иконка и текст, у выбранной реакции — трейт и рамка.
- Тосты зачитываются VoiceOver (это уже делает `AppModel.present`).
- `@Environment(\.accessibilityReduceMotion)`: при включённом — без перемещений, только смена прозрачности.
- Анимируются только прозрачность и трансформации, и только в ответ на действие человека.
